Detailed Task Execution SpecificationsTask 1.1: World Coordinate Space & Viewport Geometry Specification1. GoalEstablish a 2D orthographic spatial coordinate system ($1280 \times 720$ logical spatial units) defining pixel-to-world unit conversions, lane bounding regions, Home Base boundaries, and spawner entry points.   2. Explanation & Technical GuidanceIn 2D engines built on Modern OpenGL, rendering uses an orthographic projection matrix $M_{proj}$ generated via glm::ortho(left, right, bottom, top, zNear, zFar). Establishing an explicit 2D coordinate system prevents spatial misalignment when rendering sprites, computing bounding box collisions, or unprojecting mouse clicks.   World Coordinate Bounds: $X_{min} = 0.0f$, $X_{max} = 1280.0f$, $Y_{min} = 0.0f$, $Y_{max} = 720.0f$Projection Matrix Formulation:glm::mat4 projection = glm::ortho(0.0f, 1280.0f, 0.0f, 720.0f, -1.0f, 1.0f);Region Allocation:Top UI Toolbar Region: $Y \in [640.0f, 720.0f]$ (80 units high)   Bottom Ground Decor Region: $Y \in [0.0f, 80.0f]$ (80 units high)   Playable Central Battleground: $Y \in [80.0f, 640.0f]$ (560 units high), divided into 4 horizontal lanes   Lane Coordinates Breakdown:Lane 0: $Y_{min} = 80.0f$, $Y_{center} = 140.0f$, $Y_{max} = 200.0f$ (Height: 120 units)Lane Buffer 0-1: $Y \in [200.0f, 220.0f]$ (20 units vertical buffer)Lane 1: $Y_{min} = 220.0f$, $Y_{center} = 280.0f$, $Y_{max} = 340.0f$ (Height: 120 units)Lane Buffer 1-2: $Y \in [340.0f, 360.0f]$ (20 units vertical buffer)Lane 2: $Y_{min} = 360.0f$, $Y_{center} = 420.0f$, $Y_{max} = 480.0f$ (Height: 120 units)Lane Buffer 2-3: $Y \in [480.0f, 500.0f]$ (20 units vertical buffer)Lane 3: $Y_{min} = 500.0f$, $Y_{center} = 560.0f$, $Y_{max} = 620.0f$ (Height: 120 units)Horizontal Boundaries:Home Base Boundary ($X_{home}$): $X = 160.0f$. GoalFormulate mathematical algorithms for AABB spatial collision detection, high/low projectile dodging, defense unit shielding, and damage red tint color interpolation.   2. Mathematical FormulationsAABB Overlap Predicate:
Boxes $A$ and $B$ collide if and only if:$$\text{Overlap}_X = (A_{min.x} \le B_{max.x}) \land (A_{max.x} \ge B_{min.x})$$$$\text{Overlap}_Y = (A_{min.y} \le B_{max.y}) \land (A_{max.y} \ge B_{min.y})$$$$\text{IsColliding}(A, B) = \text{Overlap}_X \land \text{Overlap}_Y \land (A_{lane} == B_{lane})$$Parabolic Jump Arc (Evasion vs Low Projectiles):
When W/Up is pressed on a selected lane, non-defense player units execute vertical displacement:
   $$y_{offset}(t) = 4.0 \cdot H_{max} \cdot \left( \frac{t}{T_{jump}} \right) \cdot \left( 1.0 - \frac{t}{T_{jump}} \right)$$(Where $H_{max} = 60.0f$ units, $T_{jump} = 0.8f$ seconds, $t \in [0, T_{jump}]$).Low projectiles occupy $Y_{proj} \in [Y_{center} - 40, Y_{center}]$. If $y_{offset}(t) > 35.0f$, the player clears the projectile's Y-bounds, dodging damage.   Duck Scaling Equation (Evasion vs High Projectiles):
When S/Down is pressed on a selected lane, non-defense player bounding height scales down:
   $$H_{duck} = H_{normal} \cdot 0.5f$$High projectiles occupy $Y_{proj} \in [Y_{center} + 10, Y_{center} + 50]$. While ducking, the player's top bound $Y_{max} = Y_{center} + 10$, allowing high projectiles to pass safely overhead.   Defense Unit Shielding Algorithm:
For an incoming enemy projectile moving leftward along lane $L$:Sort friendly units in lane $L$ horizontally by $X$-position ascending.If an active DefensePlayer exists at $X_{def}$, any friendly unit at $X_{friendly} < X_{def}$ is shielded from projectile impacts.   Damage Red Tint Color Interpolation:
As health decreases, fragment shader red tint multiplier increases:
   $$\text{Factor}_{red} = 1.0f - \left( \frac{\text{Health}_{current}}{\text{Health}_{max}} \right)$$$$\vec{C}_{render} = \begin{bmatrix} 1.0f \\ 1.0f - \text{Factor}_{red} \\ 1.0f - \text{Factor}_{red} \end{bmatrix}$$Task 1.6: Economy, UI Card Rules & Wave Progression Spawner Specifications1.
